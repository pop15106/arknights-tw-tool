# 版本化資料與本機保存契約

本文件對應 2026-11-13 原型，含後續完成的公開資料集升版、撤銷與圖鑑欄位。核心實作位於 `src/domain/model.ts`、`src/domain/import.ts`、`src/storage/database.ts` 與 `src/storage/backup.ts`；圖鑑轉換與顯示位於 `src/catalog/build.ts`、`src/OperatorEncyclopedia.tsx`。格式版本仍為 **1**，產品固定 `arknights`、服別固定 `tw`。格式支援不代表任何帳號 API 已授權、OCR 已辨識或真機大量匯入已驗收。

## 資料分層

| 層次 | 契約與限制 |
| --- | --- |
| 資料集 `Dataset` | `metadata` 記錄 ID、版本、產品、服別、`demo`／`personal` 命名空間、有效期間、取得日期、來源、授權狀態及 SHA-256；`operators` 保存幹員定義 |
| 幹員定義 | 穩定 ID、繁中顯示名稱、別名、1–6 星、職業、分支、陣營、技能 ID／名稱、模組 ID／名稱／種類、本服可用狀態；另可帶本機肖像路徑、技能各級說明與天賦條件版本 |
| 個人幹員 `OwnedOperator` | `operatorId` 對應定義；`fields` 以固定欄位名及技能／模組穩定 ID 保存證據；禁止部分姓名比對 |
| 欄位證據 `Evidence` | `known` 必須帶值；`unknown`、`not-applicable` 禁止帶值。來源、匯入時間、人工確認為必要；資料時間、信心及本機素材位置為選填 |
| 匯入批次 | 原始來源種類由來源文字描述、內容 SHA-256、完整／局部宣告、轉換器版本、正規化候選、兩側衝突證據、逐欄決策、結果數量、重複或撤銷關係 |
| 應用狀態 `AppState` | 格式版本、本機 `local-` 設定檔 ID、交易修訂版本、資料集、幹員庫、基建／分析設定、批次及最近一次撤銷快照；快照保存匯入前的幹員庫與資料集 |

`known()`、`unknown()`、`sealDataset()`、`createEmptyState()` 為建構輔助函式。所有外部 JSON 與持久化邊界仍執行 runtime 驗證；TypeScript 型別本身不是驗證。

## 圖鑑定義與顯示

`portrait`、技能的 `levels` 及 `talents` 均為可選欄位，未帶這些欄位的既有 v1 定義仍可讀取；有提供時須通過巢狀白名單與型別驗證，並納入資料集 checksum 與備份。肖像只接受 `/assets/operators/<檔名>.png` 的本機路徑，不接受遠端網址或路徑穿越；路徑有效不代表圖片檔已存在，載入失敗時顯示替代提示。

技能 `levels` 最多 10 筆，每筆包含唯一的 1–10 整數級別與最多 6000 字元的非空說明。畫面將 1–7 顯示為技能等級、8–10 顯示為專精 1–3；切換說明只供查閱，不修改養成紀錄，也不證明已解鎖或已專精。只有技能 ID 允許尾端數字括號，例如 `skcom_atk_up[2]`，總長仍限 101 字元；幹員、模組及資料集 ID 沿用原規則。

`talents` 最多保存 30 筆條件版本，每筆含名稱、最多 6000 字元的非空說明、精英 0–2、等級 1–90 與潛能 1–6。同名天賦可保留多個版本，畫面依目前養成紀錄標示條件未滿足、待核對或對應階段；同名版本不全部相加，未人工確認的符合條件仍標為候選。這是資料條件比對，不是完整戰鬥效果計算。

公開資料轉換器依穩定 ID 合併幹員、轉職、技能與模組，將遊戲標記與參數轉為純文字；未能解析的參數明示 `〔數值待核對〕`。公開鏡像資料包的授權狀態及本服可用狀態仍為 `unknown`，不因圖鑑已有說明就視為已授權、已開放或已逐項核對遊戲數值。

## 欄位語意

| 欄位 key | 已知值範圍／意義 |
| --- | --- |
| `owned` | 布林，未知不等於未持有 |
| `elite` | 0–2，未知不等於精英零 |
| `level` | 1–90，僅通用界限，尚未逐稀有度核對精英階段等級上限 |
| `potential`、`trust`、`skillLevel` | 分別 1–6、0–200、1–7；技能等級與專精分開 |
| `mastery:<skillId>` | 0–3；已知零、未知及不適用不同 |
| `equippedSkill` | 定義中的技能 ID 或 `none`；未知另用狀態表示 |
| `moduleAvailable:<moduleId>` | 本服是否開放，不由順序、鎖頭或藍框推斷 |
| `moduleUnlocked:<moduleId>` | 個人是否已解鎖，與本服開放不同 |
| `moduleLevel:<moduleId>` | 0–3；沒有讀到的等級維持未知 |
| `equippedModule` | 定義中的模組 ID 或 `none`；與已開放、已解鎖不同 |

模組可表達「未知」「本服未開放」「已開放但未解鎖」「已解鎖」「已裝備」。本輪尚未加入所有遊戲規則的跨欄位一致性判斷，不將通用範圍驗證說成完整遊戲合法性驗證。

素材位置只接受本機 `assetId`、圖片／影片種類、選填毫秒時間及 `originalRetained`。它不是可遠端開啟的網址；`originalRetained:false` 表示原檔未保存。此原型沒有原圖保存器或 OCR 轉換器。

## 匯入與衝突

1. `parseImportText()` 解析最多 10 MB 的工具 JSON；`validateImportDocument()` 嚴格核對巢狀白名單、欄位型別、範圍、穩定 ID 與版本。
2. `previewImport()` 驗證資料包 SHA-256，對相同 ID 去重、補成明確未知、產生新增／變更／重複／衝突／缺漏數量。缺漏數量是候選中未知欄位數，不是辨識正確率。
3. 空庫且沒有批次時，可採用相同命名空間的新資料包。已有資料後，僅在目前及新資料包均為 `personal` 命名空間、`arknights`／`tw`、ID 為 `arknights-tw-public-catalog` 時允許相容升版：新 `validFrom` 不得早於目前日期（相同日期可升版），且新定義必須通過既有幹員庫、全部批次候選及衝突證據的完整狀態驗證；缺少這些資料仍引用的幹員、技能或模組 ID 時拒絕。舊撤銷快照仍以自身資料集驗證。公開資料集的日期檢查也適用空庫；其他資料包 ID、版本或 checksum 改變仍須另做遷移設計。
4. 相同欄位的不同值、較舊來源、低於 0.8 的信心或相對較低信心，集中成兩側選擇。0.8 是原型人工檢查政策，**不是經校準 OCR 成功機率**。
5. 同批兩個不同值也需選擇；左側可能是第一候選，不一定是既有資料。若同批有三個不同值，或兩個候選加上既有值形成三值，明確拒絕並要求拆分，不偷偷取最大值。
6. 普通未知欄位不得覆寫已知。人工明確標示 `manuallyConfirmed:true` 的撤回值可將已知改回未知，但必須經衝突確認；同值人工確認會更新證據。
7. `applyImport()` 檢查原預覽的完整狀態、revision 及資料集內容，重新核對升版相容性，所有衝突有決策才能產生新狀態；此時尚未寫入資料庫。每次重匯仍留批次，不重複建立幹員。
8. 不論來源宣告完整或局部，本輪合併均不刪除未出現幹員；`complete` 是未經外部證實的來源宣告，不會啟用整庫取代。備份復原另有明確確認的整份取代流程。

`undoLastImport()` 回復最近一次匯入前的幹員庫，保留所有既有批次並新增撤銷紀錄，不提供多層撤銷。若目前及快照資料集皆為上述指定繁中公開資料集，會嘗試回復快照中的舊資料集；只有回復後的完整狀態仍通過驗證才採用。例如純名稱更新可回復舊定義與 checksum；若保留的批次已引用新增幹員或技能 ID，則保留新版定義，讓全部歷史仍可解釋。其他資料集維持已採用版本。取消預覽不會新增批次或改寫狀態。

## 保存與故障保護

使用單一 IndexedDB `state` object store 的 `active` 快照。`saveState(db,next,expectedRevision)` 在同一 `readwrite` 交易內讀取目前修訂、比較後才 `put`，必須 `next.revision=expectedRevision+1`；首次空庫使用 `expectedRevision=-1`、state revision 0。交易成功之前不得向使用者宣告保存完成。

兩個分頁同時儲存相同修訂，只能一個成功；落後分頁會收到需重新載入、重新預覽的錯誤。同一庫不能跨命名空間或設定檔 ID 覆寫。示範與私人資料使用不同資料庫名稱，並在核心再次檢查命名空間，示範幹員 ID 強制以 `demo-` 開頭。

容量錯誤、真正交易中止、版本過新、升級受阻與無效舊資料均保留既有資料，不呼叫 `clear()` 或以刪庫重建作補救。被阻擋且已回報失敗的 open request 若稍後放行，升級交易會中止，不延後偷偷寫入。有效 AppState 與備份設 20 MB 上限、2000 位幹員、1000 筆批次；超過需另外規劃可驗證的封存，不自動刪歷史。

`queryPersistence()` 查容量與持久許可；`requestPersistence()` 由介面明確觸發。取得許可仍可能被使用者清除，不能取代備份。真機 Safari、加入主畫面模式、離線與換機行為需另外驗收。

## 備份與格式版本

備份 envelope 包含 `format:'arknights-roster-backup'`、`formatVersion:1`、匯出時間、整個 state 的 SHA-256 與 state；保存未知狀態、人工證據、設定、批次及撤銷快照。`parseBackup()` 先檢查格式、大小、型別、版本、範圍與 checksum，再回傳候選 state，**不直接寫入**。介面必須列出取代差異，使用者確認後保留目前 profile ID、提升目前 revision，透過原子交易取代。

SHA-256 可發現意外損壞或未同步更新 checksum 的修改；它不是簽章、授權證明或可信來源保證。宣稱 `permitted` 的資料包仍須另附授權研究證據。所有欄位採白名單；額外的 token、cookie、uid、email 等欄位拒絕，文字也攔截常見電子郵件與憑證標記，但不宣稱能識別任意偽裝成一般文字的秘密。不要把私人識別資訊放進來源描述。

沒有可驗證的既有 v0 格式，故本輪不虛構遷移器：舊版／未來版備份拒絕並要求保留原檔；較新 IndexedDB schema 不降級、不清空。這是資料保護策略，並非已完成跨版本遷移。

## 已執行測試與待驗證邊界

Node 測試位於 `tests/core.test.ts`、`tests/database.test.ts`：100 筆合成批次、重複／補齊、同批雙候選與三值拒絕、舊圖與人工證據、人工撤回未知、低信心、專精零／未知／不適用、預覽過期、命名空間、壞 checksum／版本／巢狀欄位、JSON 容量、備份 round-trip、關閉重開、並行修訂、容量故障、交易 abort、blocked 升級、舊／新 DB 格式保留。公開資料集另覆蓋同日相容升版、舊日期與其他資料集拒絕、既有及歷史 ID 保護、預覽後資料集改動拒絕，以及撤銷回復舊定義或保留新版的兩種情況與備份復原。

`tests/model-catalog.test.ts`、`tests/catalog.test.ts` 覆蓋舊 v1 定義相容、新圖鑑欄位的白名單與範圍、技能括號 ID、肖像路徑、checksum 與備份保存，以及合成表格的轉職／模組歸屬、技能與天賦文字轉換。這些測試驗證資料契約與轉換，不證明每位幹員的實際遊戲數值、天賦效果或所有畫面互動均已驗收。

IndexedDB 自動測試使用 `fake-indexeddb`；容量與 blocked 故障為刻意注入，不能推論為已測 iOS 真實磁碟壓力。100 筆為虛構結構化資料，不是 100 名真實幹員辨識結果。手機大量資料取得、OCR 正確率、影片解碼、iPhone 真機保存及備份移轉均未由這些測試證明。
