## 統計與樣本紀錄格式

每次實測至少記錄：來源種類、授權依據、產品與服別、遊戲／工具／轉換器版本、資料時間與匯入時間、裝置／瀏覽器、完整或局部、去識別樣本雜湊、人工基準建立者及覆核紀錄。原圖與影片留在私有區，不加入公開 Git、URL、日誌或分析事件。

逐欄保存四個互斥計數：**正確、錯誤、未知、不適用**。分母與排除原因須顯示。未知不併入正確；人工修正後的結果不得回填成辨識原始正確。另記錄需處理列數／總列數、修正欄位數、操作次數與時間。

當來源確定完整時，另外核對持有幹員總數、每個穩定 ID、重複及遺失。只有通過這個範圍檢查，才能把某必要欄位的缺失標為「缺漏（實測）」；取得局部資料時仍保持未知。

## 匯入與保存的不變條件

- 來源先產生候選資料，再顯示預覽與集中衝突確認，確認前不修改正式幹員庫。
- 未知不覆蓋已知；舊資料、低信心及人工更正衝突不靜默覆蓋。
- 以穩定 ID 去重；局部匯入不刪除未出現幹員；重複批次不得產生重複幹員。
- 合併必須可撤銷；整庫取代需顯示差異、確認來源完整性並由使用者明確選擇。
- 備份含格式版本、產品／服別、資料集版本、未知狀態、欄位證據與人工更正；不含登入憑證。
- 復原先驗證格式、版本、範圍與資料；錯誤、容量不足、交易失敗不得先清空原資料。

以上是實作與驗收要求。本輪程式實際完成度、執行過的自動化測試、測試數量及 iPhone 待測項，由同輪測試報告記錄，不由此研究能力表代替。
