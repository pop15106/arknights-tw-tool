# SKPORT 與多圖辨識整合驗證

日期：2026-11-13（Asia/Taipei）。本輪承接使用者要求：參考 RIIC 流程研究及實作 SKPORT 轉接，並由另一個 agent 處理六張真實截圖。

## 變更範圍

- SKPORT 公開登入鏈追蹤與研究文件；登入、權限、服別、完整度分開記錄。
- 純離線 SKPORT 轉換器、合成測試與命令列入口；沒有新增後端或網路資料讀取。
- Windows 本機多圖 OCR、版型解析、精確姓名候選分組與來源追蹤；私人素材與結果位於 `private-fixtures/`。
- 匯入視窗新增多圖結果檢視、原圖 SHA-256 核對與列位置標示；正式 ID 未對應前不提供保存至幹員庫的按鈕。
- 匯入視窗顯示 SKPORT 四步流程與官方網站連結；不把該連結視為帳號連接。

既有示範／個人 IndexedDB、合併規則與備份格式未更換。沒有安裝新套件、修改帳號或系統執行政策、上傳照片、正式部署、建立 Git 儲存庫或推送。

| CLI 成功案例 | 實際讀合成研究封裝＋校驗資料集，產生 1 名局部候選，回報 4 項限制；沒有帳號網路請求 |

## 尚未成立的驗收

SKPORT 真實登入／授權／撤銷、G0–G5、完整持有總數對照與養成欄位實測仍未通過。離線封裝是本專案研究格式，不是已存在的官方 JSON 匯出功能。

OCR 的精確姓名分組不是正式 ID 去重，也不能證明全庫完整。尚未完成圖示辨識、技能／模組 ID 對應、至少 100 名混合養成、iPhone 直接選圖辨識與少手動修正門檻。桌面結果檢視不能取代 iPhone 真機測試。

## 最終整合檢查

- 最終 `npm test`：48／48 通過，無失敗、無跳過。
- 最終 `npm run build`：TypeScript 檢查與 Vite 建置通過；產物位於 `dist/`。
- 六張真圖最終辨識結果：60 列、58 個文字候選群組、2 列重疊；結果為 `private-fixtures/screenshots-2026-11-13/review-final.json`。這不是正式幹員 ID 匯入完成，數值準確率與參考分母見 [辨識報告](screenshot-recognition.md)。
- OCR guards：8 通過、1 跳過；環境無法建立真 junction，未把該項列為實機通過。
- 已登入的 SKPORT 個人頁、《明日方舟》社群板塊及網站設定頁，本次可見介面未出現幹員匯出或授權本工具的入口。這是所查頁面的觀察，不代表官方所有產品與 App 都沒有相關功能。
- 官方設定的「客服中心」連至 [SKPORT 支援中心](https://gryphline.helpshift.com/hc/zh-hant/12-skport/)，頁面提供「聯絡我們」。未填寫或送出詢問，未更改帳號、綁定角色或擷取憑證。
- [本機接入研究](skport-local-prototype.md) 已記錄公開 SDK 初始化、登入回呼、交換與簽章線索；使用官方 SDK 的自製接入仍屬非官方整合。尚未建立可用的帳號連線服務，也未取得真實帳號 JSON。

以上通過的是軟體測試與本機研究流程；官方接入、真實 API 資料完整性與 iPhone 驗收仍未通過。
